# English ST — дизайн сайта школы английского языка

Дата: 2026-10-25. Статус: черновик на согласование.

Пометка **[моё решение]** — то, что заказчик не решал явно; это предложение, которое можно оспорить. Всё остальное — решения заказчика.

## 1. Зачем и для кого

Сайт для детской школы английского. Главные пользователи — дети со смартфонами: каждый день проходят короткое задание как в Duolingo, копят серию дней и штампики, меняют штампики в магазине на призы, общаются с учителем и группой. Учитель через сайт ведёт группы, составляет задания, награждает и модерирует.

Успех: ребёнок открывает сайт на телефоне каждый день, сам без подсказок проходит задание за пару минут, и ему хочется вернуться завтра; учителю удобно вести всё с телефона.

## 2. Цели, не-цели, анти-цели

**Цели**
- Три роли: ученик, учитель, администратор.
- Ежедневные задания пяти типов, тесты и пулы вопросов, серия дней.
- Штампики нескольких видов (валют) и магазин призов с заявками учителю.
- Чаты: ученик ↔ учитель и общий чат группы, с фильтром мата.
- Интерфейс сначала под телефон, в стиле Duolingo, без маскота, максимально простой.
- Безопасный вход для детей без email.

**Не-цели (сейчас)**
- Озвучка, распознавание речи.
- Регистрация «с улицы», email, восстановление пароля по почте.
- Онлайн-оплата, расписание занятий, журнал посещаемости.
- Нативные приложения (будет PWA — установка сайта на главный экран).
- Push-уведомления (возможно позже).
- Импорт вопросов из таблиц и документов — готовых материалов пока нет; добавим позже при необходимости.
- Политика конфиденциальности и фиксация согласия родителей — заказчик решил не делать.
- Конвертация штампиков между видами — заложить в модель, правила и курсы определит заказчик позже.

**Анти-цели (провал, даже если «работает»)**
- Ребёнок путается в интерфейсе или ему нужно что-то объяснять.
- Сайт заметно нагружает VPS, на котором живут ещё два сайта.
- Дети видят мат или могут писать незнакомым людям.
- Детские фото доступны посторонним по ссылке.

## 3. Ограничения

- VPS в РФ: Ubuntu 24.04, 1 vCPU, 1 ГБ RAM, 20 ГБ диска. На нём уже работают два сайта заказчика (`rieltor_site` на порту 8000, `art_site` на 8001).
- **Всё на VPS, никакого GitHub Actions/внешней сборки.** Развёртывание — как у соседних сайтов (см. §11).
- Без Node и сборки фронтенда — как у соседних сайтов.
- Домены: `english-st.ru` (основной), `english-st.online` (редирект на основной).
- Масштаб: 1 учитель, до 15 учеников; закладываем рост до десятков учителей без переделки.
- Персональные данные: храним только имя, фамилию и фото ребёнка. Сервер в РФ.
- Интерфейс на русском.
- Репозиторий: https://github.com/Stonkix/english-st.git. В коммитах Claude соавтором не указывается.

## 4. Подходы

**Развёртывание.** Рассматривали: (А) PostgreSQL + Docker Compose, (Б) SQLite без Docker, (В) SQLite + Docker с образами из GitHub Actions. Заказчик отказался от внешней сборки и выбрал развёртывание как у двух существующих сайтов: systemd + nginx + SQLite, обновление `git pull`. Docker и PostgreSQL отпали как лишняя нагрузка на 1 ГБ RAM при 16 пользователях.

**Фронтенд.** Рассматривали: (А) Jinja2 + HTMX + свой JS, как у соседних сайтов; (Б) React-SPA со сборкой на VPS (нужны Node и swap, сборка до 600 МБ RAM на каждом обновлении). Заказчик выбрал **А**; анимации делаем на CSS/JS.

## 5. Требования по разделам (решения заказчика)

### 5.1 Учётные записи
- У каждого: имя, фамилия, аватар (своё фото), смена пароля.
- Учитель создаёт учеников внутри группы: логин + временный пароль; при первом входе ученик обязан задать свой пароль.
- Регистрации нет, email нет. Забытый пароль сбрасывает учитель или админ.
- Структура: **1 ученик = 1 группа = 1 учитель** (у учителя может быть несколько групп).
- Пароль: минимум 10 символов, латиница, обязательно есть строчная, заглавная и цифра; спецсимволы разрешены, но не обязательны.
- Блокировка: после 5 неверных паролей вход блокируется на 10 минут **по паре «логин + IP»** (чтобы одноклассник не мог заблокировать чужой аккаунт), плюс общий лимит неудачных попыток с одного IP.

### 5.2 Задания
- Ежедневное задание обновляется в **00:00 по Москве**.
- Учитель для каждой группы настраивает: число вопросов, число попыток пройти заново, перемешивание вопросов, какие штампики (каких видов и сколько) выдаются за прохождение.
- Серия дней подряд — нужна.
- Типы вопросов в MVP: выбор текстового ответа, выбор картинки, ввод ответа, сборка фразы из слов, «соедини пары». Озвучки нет.
- Учитель составляет тесты и может назначить конкретный тест. Если тест не назначен — вопросы берутся из пула и меняются каждый день.
- Пулов может быть несколько; пул назначается группам. У пула обязательно: название, описание, уровень из списка A1, A1+, A2, A2+, B1, B1+, B2, B2+, C1, C1+, C2, C2+.

### 5.3 Штампики
- Несколько видов, каждый — отдельная валюта со своим балансом.
- Виды можно будет конвертировать (например, 10 простых → 1 редкий); правила уточняются позже.
- Учитель выдаёт штампики вручную; также они начисляются за ежедневное задание по настройкам группы.

### 5.4 Чат
- Ученик ↔ учитель (личный) и чат группы (ученики + учитель).
- Можно стикеры и картинки.
- Учитель может удалить сообщение.
- Мат заменяется словом из перечня.

### 5.5 Магазин
- У каждой группы свой магазин; позиции создаёт учитель группы: название, описание, картинка, цена в штампиках.
- Учёта остатков нет.
- Заявка ученика уходит учителю его группы.

## 7. Модель данных

- **User**: id, login (уникальный, латиница/цифры/`._-`, 3–32), password_hash, role (`student`/`teacher`/`admin`), first_name, last_name, avatar (имя файла), group_id (только у ученика), must_change_password, is_active, created_at.
- **Group**: id, name, teacher_id, created_at. Группа учителя; ученик в ровно одной группе.
- **Session**: token_hash, user_id, created_at, last_seen_at, expires_at, ip, user_agent.
- **LoginAttempt**: key (`login|ip` или `ip`), failures, last_failure_at, blocked_until.
- **Pool**: id, owner_id (учитель), title, description, level (enum из 12 значений), created_at.
- **GroupPool**: group_id, pool_id — какие пулы назначены группе.
- **Question**: id, owner_id, pool_id (nullable — вопрос, написанный прямо в тесте), type (`choice_text`/`choice_image`/`text_input`/`word_bank`/`match_pairs`), prompt (текст задания), payload (JSON, схема зависит от типа, валидируется Pydantic), image (опционально), is_active, created_at.
- **Test**: id, owner_id, title, description, created_at. **TestQuestion**: test_id, question_id, position.
- **Assignment**: id, test_id, group_id, student_id (nullable — назначение конкретному ученику), date (дата по Москве). Назначение ученику главнее назначения группе.
- **DailySettings** (на группу): question_count, max_attempts, shuffle_questions, shuffle_options. **DailyReward**: group_id, stamp_type_id, amount, min_score_percent.
- **Attempt**: id, student_id, date (МСК), source (`test`/`pool`), test_id (nullable), question_ids (JSON, зафиксированный набор), started_at, finished_at, correct_count, total_count. **AttemptAnswer**: attempt_id, question_id, answer (JSON), is_correct, had_typo.
- **Streak** (вычисляемое или кэш в User): current_streak, best_streak, last_completed_date.
- **StampType**: id, name, icon, color, sort_order, is_active. Общие на школу, задаёт админ [моё решение].
- **StampTransaction**: id, student_id, stamp_type_id, amount (±), reason (`manual`/`daily`/`order`/`refund`/`conversion`), comment, actor_id, related (attempt/order id), created_at. Баланс = сумма по виду; журнал не редактируется.
- **ConversionRule** (на будущее): from_type, from_amount, to_type, to_amount, is_active. В MVP таблица может быть пустой и без интерфейса.
- **ShopItem**: id, group_id, title, description, image, price_type_id, price_amount, is_active.
- **Order**: id, student_id, item_id, price_type_id и price_amount (снимок цены), status (`pending`/`issued`/`rejected`), teacher_comment, created_at, decided_at.
- **ChatRoom**: id, kind (`group`/`direct`), group_id, student_id (для direct). Комнаты создаются автоматически: одна на группу и одна «ученик ↔ его учитель».
- **ChatMessage**: id, room_id, author_id, kind (`text`/`image`/`sticker`), text_original, text_shown, sticker_id, image, was_filtered, deleted_at, deleted_by, created_at. **ChatReadMark**: room_id, user_id, last_read_message_id.
- **BadWord**: id, pattern (корень/шаблон), lang. **BadWordException**: слова-исключения. **ReplacementWord**: id, word.

## 8. Ключевые механики

### 8.1 Вход, сессии, пароли
- Вход по логину и паролю. Ошибка всегда общая: «Неверный логин или пароль». При блокировке — сколько минут осталось.
- `login_guard` по образцу соседних сайтов, но ключ `логин|IP`: 5 ошибок → блок на 10 минут. Отдельно ключ `IP`: 20 ошибок за 10 минут по любым логинам → блок IP на 10 минут [моё решение по числу]. Плюс `limit_req` в nginx на `/login`. Учитель снимает блок своему ученику, админ — любому; есть CLI `python -m app.cli unlock`.
- Сессия — случайный токен в cookie (httpOnly, Secure, SameSite=Lax), в базе хранится хеш токена. Срок 30 дней со скольжением [моё решение]. Смена или сброс пароля и деактивация удаляют сессии пользователя (кроме текущей при смене своего пароля).
- Временный пароль генерирует система (удовлетворяет требованиям, без похожих символов `0O1lI`), показывается учителю один раз. Флаг `must_change_password` отправляет на экран смены пароля до любых других действий.
- Логин учитель вводит сам, система подсказывает транслитерацию имени [моё решение].
- Проверка пароля: `^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)[\x21-\x7E]{10,}$`. На странице — живая подсказка, каких условий не хватает.
- Имя и фамилию ученика меняет учитель; ученик сам меняет аватар и пароль [моё решение — чтобы дети не переименовывались в грубые слова].
- Первого админа создаёт CLI: `python -m app.cli create-admin`. Админ создаёт учителей; учитель — группы и учеников [моё решение]. У аккаунта одна роль; `admin` — надмножество `teacher` (может владеть группами), `require_role("teacher")` пропускает и админа.

### 8.2 Ежедневное задание
- «Сегодня» — дата по Москве. Задание на день для ученика:
  1. есть назначение теста ученику на сегодня → этот тест;
  2. иначе есть назначение теста его группе → этот тест;
  3. иначе случайные `question_count` вопросов из всех пулов группы. Выбор детерминированный (seed = ученик + дата), чтобы обновление страницы ничего не меняло; по возможности исключаются вопросы, которые ученик видел за последние 7 дней [моё решение].
  4. Нет ни теста, ни пулов → экран «Сегодня заданий нет».
- Попытки: до `max_attempts` за день. При повторной попытке набор вопросов тот же, порядок перемешивается, если включено.
- Награда по `DailyReward`: при первой попытке за день, где результат ≥ `min_score_percent`, начисляется указанное количество штампиков указанного вида; каждое правило срабатывает не чаще раза в день [моё решение].
- Серия: день засчитывается, если ученик завершил хотя бы одну попытку. День, когда заданий не было, серию не прерывает [моё решение]. Показываются текущая и лучшая серия.

### 8.3 Типы вопросов и проверка
| Тип | payload | Ответ ученика |
|---|---|---|
| `choice_text` | options[], correct_index | выбор одного варианта |
| `choice_image` | options[{image, caption}], correct_index | выбор карточки |
| `text_input` | accepted[] — список правильных вариантов | ввод текста |
| `word_bank` | answer (правильная фраза), distractors[] | нажатиями собрать фразу из плиток |
| `match_pairs` | pairs[[left, right]] до 6 пар | соединить пары |

- Нормализация текста: регистр, пробелы по краям и повторные, конечные `.!?`, апострофы `’` → `'`, `ё` → `е`.
- Опечатка: расстояние Левенштейна 1 при длине ответа ≥ 5 символов — засчитывается как верно с пометкой «Почти! Правильно пишется …» [моё решение].
- Проверка выполняется на сервере (ответ отправляется после нажатия «Проверить»); правильный ответ в HTML страницы не попадает.
- `match_pairs`: засчитано, если все пары верные; ошибки внутри вопроса подсвечиваются сразу (как в Duolingo).

### 8.4 Плеер задания (экран как у Duolingo)
- Сверху: крестик выхода и полоса прогресса. Внизу — большая кнопка «Проверить», после проверки выезжает плашка: зелёная «Отлично!» или красная с правильным ответом, кнопка «Дальше».
- В конце — экран результата: сколько верно, начисленные штампики, серия, лёгкое конфетти.
- Реализация: страница плеера получает вопросы без ответов; JS по одному показывает вопросы и шлёт ответ на `POST /daily/answer`. Обновление страницы продолжает попытку с текущего вопроса.

### 8.5 Фильтр мата
- Словарь корней на русском и английском + исключения (чтобы не цеплять обычные слова) + перечень слов-замен. Всё редактирует админ.
- Перед проверкой текст нормализуется: латинские двойники → кириллица (`a e o p c x y k m h b` и т. п.), цифры-двойники (`0→о`, `3→з`, `6→б`, `@→а`), удаление разделителей между буквами (`х.у.й`, `х у й`), схлопывание повторов (`бляяя`).
- Найденное слово целиком заменяется случайным словом из перечня. В базе хранятся и исходный, и показанный текст; исходный видят учитель группы и админ (пометка «отфильтровано») [моё решение].
- Фильтр работает в чате; имена при создании аккаунта проверяются им же с отказом.

### 8.6 Чат
- Комнаты создаются автоматически: «группа» и «ученик ↔ учитель». Ученик видит две комнаты; учитель — все свои.
- Транспорт: WebSocket `/ws`, авторизация той же cookie, проверка заголовка Origin. Сервер держит соединения в памяти и рассылает сообщения участникам комнаты.
- Отправка текста и стикера — через WebSocket; картинки — `POST` загрузкой, после обработки сервер рассылает сообщение. При обрыве связи — переподключение с нарастающей паузой и догрузка пропущенного по id последнего сообщения.
- История — порциями по 50 при прокрутке вверх.
- Ограничения: текст до 1000 символов; не чаще 1 сообщения в секунду и 20 в минуту на пользователя; картинки до 15 МБ на входе.
- Учитель удаляет любое сообщение в своих комнатах: у всех оно сразу заменяется на «Сообщение удалено». Ученик может удалить своё [моё решение].
- Счётчик непрочитанных на вкладке «Чат».
- Стикеры — набор картинок в `static/stickers` со свободной лицензией (например, Microsoft Fluent Emoji, MIT); выбор набора — за исполнителем.

### 8.7 Штампики
- Учитель выдаёт или списывает штампики ученику своей группы: вид, количество, комментарий (необязательный).
- Ученик видит балансы по видам и историю операций.
- Начисление за задание — по §8.2. Конвертация — позже по `ConversionRule`.

### 8.8 Магазин и заявки
- Ученик видит позиции своей группы и свои балансы; кнопка «Обменять» активна, если хватает штампиков нужного вида.
- Заявка: в одной транзакции (`BEGIN IMMEDIATE`) проверяется баланс, создаётся заказ и списание. Снимок цены сохраняется в заказе.
- Учитель видит очередь заявок со счётчиком; действия «Выдано» и «Отклонить» (с комментарием). Отклонение возвращает штампики.
- Ученик видит статусы своих заявок. Пока заявка ждёт, ученик может её отменить с возвратом [моё решение].

## 9. Экраны

Мобильный первым; на ширине ≥ 900px нижнее меню становится левой колонкой, контент — по центру шириной до ~600px.

**Ученик** (нижнее меню: Задание · Чат · Магазин · Профиль)
- Главная: серия дней, балансы штампиков, большая карточка «Задание на сегодня» (начать / продолжить / пройдено, осталось попыток).
- Плеер задания и экран результата.
- Чат: список из двух комнат → переписка.
- Магазин: позиции, мои заявки.
- Профиль: фото, имя, смена пароля, выход, история штампиков.

**Учитель** (нижнее меню: Группы · Задания · Чат · Заявки · Профиль)
- Группы: список → группа (ученики со статусом задания за сегодня, серией, балансами) → ученик (результаты, выдать штампики, сбросить пароль, снять блокировку, редактировать).
- Задания: пулы (уровень, вопросы), тесты, редактор вопроса пяти типов с предпросмотром, назначения на даты, настройки ежедневки группы и награды.
- Магазин группы: позиции.
- Заявки: очередь.
- Результаты: по группе за день и по ученику.

**Админ** [моё решение]: роль «админ» включает все возможности учителя — владелец школы может вести свои группы с того же аккаунта. В мобильном интерфейсе у админа дополнительно вкладка «Школа»: учителя, виды штампиков, словарь фильтра и слова-замены, сброс паролей. sqladmin остаётся запасным инструментом для прямой правки данных с компьютера.

**Стиль** (по референсу Duolingo, без маскота): шрифт Nunito (свои woff2, кириллица+латиница), основной зелёный `#58CC02`, синий для выбранного, красный для ошибки; крупные «объёмные» кнопки с нижней тенью и эффектом нажатия; карточки со скруглением 16px и серой рамкой; много воздуха, крупный текст, минимум элементов на экране.

**Анимации**: нажатие кнопок, заполнение прогресса, выезд плашки результата, лёгкая тряска при ошибке, конфетти в конце, плавные переходы между страницами через CSS View Transitions (там, где браузер поддерживает); `prefers-reduced-motion` отключает движение.

**PWA**: manifest, иконки, service worker только для кэша статики (без офлайн-режима); загруженные файлы `media/` он не кэширует.

## 10. Безопасность

- Права проверяются в каждом роуте зависимостями (`require_role`) и в сервисах (учитель — только свои группы, ученик — только свои данные и комнаты).
- CSRF: SameSite=Lax + проверка `Origin`/`Referer` на всех изменяющих запросах и при подключении WebSocket.
- Загрузки: только изображения (Pillow открывает и перекодирует, остальное отклоняется), EXIF/GPS удаляются; аватар — квадрат 512px WebP; картинки чата — до 1280px WebP; картинки вопросов и товаров — до 1280px WebP.
- **Все загруженные файлы (аватары, картинки чата, вопросов и товаров) доступны только вошедшим пользователям** [моё решение — следует из анти-цели про детские фото]: Python проверяет права (картинки чата — только участникам комнаты, остальное — участникам той же группы, учителю и админу) и отдаёт файл через `X-Accel-Redirect` из закрытого `internal` location nginx, с заголовком `Cache-Control: private`. Публично отдаются только статика сайта и стикеры.
- Заголовки безопасности в nginx (как у соседних сайтов) + CSP без внешних источников.
- Нет `/docs` и OpenAPI в проде.
- При `DEBUG=false` приложение не стартует с секретами-заглушками (как у соседних сайтов).
- Ограничение частоты: вход (nginx + login_guard), сообщения чата, загрузки.
- Ежедневный бэкап базы и медиа; напоминание выносить копии с сервера.

## 11. Развёртывание (как у соседних сайтов)

- Пользователь `englishst`, код в `/srv/englishst`, venv, `pip install -r requirements.txt`.
- `deploy/englishst.service`: `uvicorn app.main:app --host 127.0.0.1 --port 8002 --workers 1 --proxy-headers --forwarded-allow-ips 127.0.0.1`, те же ограничения systemd, запись только в `data/` и `media/`.
- `deploy/nginx.conf`: статику отдаёт nginx; закрытый `internal` location для всех загруженных файлов (`media/`), доступ только через `X-Accel-Redirect`; `location /ws` с заголовками Upgrade и `proxy_read_timeout 3600s`; `limit_req` на `/login`; `client_max_body_size 16m`; `english-st.online` → 301 на `english-st.ru`; HTTPS через certbot.
- Обновление: `cd /srv/englishst && git pull && .venv/bin/pip install -r requirements.txt && .venv/bin/alembic upgrade head && systemctl restart englishst` — оформить в `deploy/update.sh`.
- `deploy/backup.sh` по cron: онлайн-бэкап SQLite + архив `media/`, хранение 14 дней.
- README с пошаговой установкой по образцу соседних сайтов.
- **Выкладывает на VPS заказчик сам.** Исполнитель доступа к серверу не имеет: всё проверяется локально (тесты + ручная проверка в браузере, в т.ч. в мобильном режиме), а скрипты деплоя и README должны работать без присмотра исполнителя.

## 12. Этапы

0. **Каркас**: структура, конфиг, БД и Alembic, базовый шаблон, CSS-кит (кнопки, карточки, поля, нижнее меню, прогресс), тесты, файлы деплоя.
